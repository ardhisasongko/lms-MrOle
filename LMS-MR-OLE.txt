## INSTRUKSI UTAMA



Bangun aplikasi baru berdasarkan konfigurasi proyek di atas.



Proyek harus dibuat di repository dan folder baru. Jangan mengubah, menghapus, atau mencampurkan proyek lain yang sudah ada.



Gunakan repository referensi hanya sebagai acuan untuk:



- Struktur frontend.

- Pola komponen.

- UI/UX.

- Responsivitas.

- Dark mode.

- Autentikasi.

- Dashboard.

- Lazy loading.

- Validasi.

- Keamanan.

- Pengujian.

- Review hasil.

- Pengelolaan deployment.



Jangan menyalin nama, identitas, teks, logo, data, atau isi bisnis dari repository referensi.



Jika ada bagian konfigurasi yang belum lengkap, buat asumsi yang masuk akal dan tuliskan asumsi tersebut sebelum implementasi. Jangan mengubah tujuan produk tanpa persetujuan.

# STACK UTAMA



## Frontend



Gunakan:



- React 19.

- React DOM 19.

- React Router DOM 7.

- Vite.

- Tailwind CSS 3.

- Lucide React.

- React Hot Toast.

- Recharts.

- jsPDF.

- jsPDF AutoTable.

- ESLint.

- PostCSS.

- Autoprefixer.



## Backend dan layanan



Gunakan:



- Cloudflare Pages untuk frontend.

- Cloudflare Workers atau Pages Functions untuk API.

- Supabase Auth untuk autentikasi.

- Supabase PostgreSQL untuk database.

- Supabase Storage jika diperlukan.

- Zod untuk validasi.

- DOMPurify atau sanitasi setara untuk konten pengguna.

- UUID untuk identifier.

- Wrangler untuk development dan deployment Cloudflare.



## AI



Jika konfigurasi menyatakan menggunakan AI, gunakan:



- OpenAI Responses API.

- Structured Output dalam format JSON.

- Zod untuk memvalidasi hasil AI.

- Cloudflare Worker sebagai penghubung ke OpenAI.

- API key hanya disimpan sebagai environment variable server.



Jika aplikasi tidak menggunakan AI:



- Jangan memasang dependency OpenAI.

- Jangan membuat endpoint AI.

- Jangan membuat tabel penggunaan token.

- Pertahankan arsitektur frontend, autentikasi, database, keamanan, dan deployment lainnya.



## Dokumen



Jika aplikasi memerlukan Word:



- Gunakan library `docx`.



Jika memerlukan PDF:



- Gunakan `jspdf`.

- Gunakan `jspdf-autotable` untuk tabel.



Jika memerlukan Excel:



- Gunakan library yang sesuai setelah menjelaskan alasan pemasangannya.



Jangan memasang dependency baru tanpa menjelaskan fungsi, manfaat, risiko, dan alternatifnya.



Gunakan versi stabil yang kompatibel. Hindari versi beta kecuali benar-benar diperlukan dan telah disetujui.



Buat serta pertahankan `package-lock.json`.

# DATABASE

Minimal siapkan tabel:



- `profiles`

- `organizations` jika diperlukan

- `ai_generations` jika menggunakan AI

- `audit_logs`

Setiap tabel harus mempertimbangkan:



- Primary key UUID.

- Foreign key.

- `created_at`.

- `updated_at`.

- Index.

- Constraint.

- Status data.

- Soft delete jika diperlukan.

- Pemisahan data pengguna.

- Pemisahan data organisasi.

- Row Level Security.

- Audit perubahan sensitif.



Buat migration SQL yang:



- Dapat dijalankan dengan aman.

- Tidak merusak data yang sudah ada.

- Tidak bergantung pada tindakan manual yang tidak terdokumentasi.

- Memiliki seed data kecil untuk development.



Jika aplikasi digunakan banyak organisasi, sekolah, perusahaan, atau lembaga, setiap data bisnis harus memiliki `organization_id`.

# ROW LEVEL SECURITY



RLS wajib diterapkan.



Aturan minimum:



- Pengguna hanya dapat membaca datanya sendiri.

- Pengguna hanya dapat mengubah datanya sendiri.

- Admin hanya mendapat akses sesuai organisasi yang dikelolanya.

- Data antarorganisasi tidak boleh tercampur.

- Service-role key tidak boleh berada di browser.

- Operasi berisiko harus dijalankan melalui endpoint server.

- Kebijakan RLS harus diuji menggunakan lebih dari satu akun.

# INTEGRASI AI



Bagian ini hanya berlaku jika aplikasi menggunakan AI.



AI harus diposisikan sebagai alat bantu, bukan sumber kebenaran tunggal.



Alur:



```text

Pengguna mengisi formulir

        ↓

Frontend memvalidasi input

        ↓

Cloudflare Worker memvalidasi request

        ↓

Worker memeriksa akun dan kuota

        ↓

OpenAI menghasilkan JSON terstruktur

        ↓

Zod memvalidasi output

        ↓

Data disimpan sebagai draf

        ↓

Pengguna memeriksa dan mengedit

        ↓

Data ditandai selesai atau disetujui

```



Aturan:



- Jangan menerima output AI bebas tanpa schema.

- Gunakan Structured Output.

- Batasi panjang input.

- Batasi panjang output.

- Maksimal satu retry otomatis.

- Cegah request ganda.

- Gunakan idempotency key.

- Simpan hasil agar tidak dibuat ulang.

- Izinkan regenerasi per bagian.

- Catat token dan estimasi biaya.

- Tetapkan kuota harian dan bulanan.

- Jangan mengirim data sensitif.

- Jangan mengirim password, token, NIK, alamat lengkap, atau data pribadi yang tidak diperlukan.

- Jangan mengarang sumber atau referensi.

- Hasil AI harus memiliki status `ai_draft`.

- Pengguna harus memeriksa hasil sebelum digunakan.



Tampilkan peringatan:



“Konten ini dibuat dengan bantuan AI dan wajib diperiksa sebelum digunakan.”

# KEAMANAN



Terapkan:



- API key hanya di server.

- Supabase service-role key hanya di server.

- RLS pada seluruh data pengguna.

- Validasi frontend dan server.

- Sanitasi konten.

- Rate limiting.

- Pembatasan ukuran request.

- Security headers.

- Content Security Policy.

- HTTPS.

- Proteksi clickjacking.

- Proteksi MIME sniffing.

- Kebijakan referrer.

- Pembatasan permission browser.

- Pesan error produksi yang aman.

- Audit log tindakan sensitif.

- Pembatasan percobaan login.

- Proteksi request ganda.

- Pembatasan kuota.

- Pemeriksaan dependency.

- Environment variable untuk seluruh secret.



Dilarang:



- Menaruh secret di frontend.

- Commit `.env`.

- Mencatat password atau token.

- Menampilkan stack trace di produksi.

- Mengandalkan frontend untuk keamanan.

- Menggunakan `localStorage` untuk menyimpan data sensitif jika tersedia metode yang lebih aman.

- Membuka CORS untuk semua origin tanpa alasan.

- Mempercayai role yang dikirim frontend.

# HOSTING



Gunakan:



```text

Cloudflare Pages

→ Frontend React



Cloudflare Workers/Pages Functions

→ API dan server-side logic



Supabase

→ Auth, PostgreSQL, dan Storage



OpenAI API

→ Generasi AI jika digunakan



Browser

→ Pembuatan Word/PDF jika aman dan memungkinkan
```

Target paket gratis Cloudflare:



- Aset statis dilayani dari Pages.

- Endpoint dinamis melalui Workers.

- Hindari pekerjaan CPU berat.

- Hindari server Express tradisional.

- Gunakan Fetch API dan runtime Web Standard.

- Siapkan arsitektur agar mudah ditingkatkan ke Workers Paid.

- Jangan menggunakan Vercel untuk proyek ini.



Buat:



- `wrangler.jsonc` atau konfigurasi Wrangler yang sesuai.

- Environment development.

- Environment production.

- Dokumentasi pemasangan secret.

- Konfigurasi SPA fallback.

- Security headers.

- Deployment dari GitHub.
